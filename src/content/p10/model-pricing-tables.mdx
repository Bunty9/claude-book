# Model & pricing cheat tables

Quick-reference tables for Claude model ids, capabilities, context windows, and pricing. Use these to make fast model-selection decisions without leaving your workflow.

<Callout type="tip" title="Prices change">
Anthropic updates pricing periodically. Always verify current rates at console.anthropic.com/settings/billing before committing to a production budget.
</Callout>

## The Claude model family

| Model id | Tier | Context window | Modalities | Best for |
|---|---|---|---|---|
| `claude-fable-5` | Fable | 1M tokens | Text, image, tool use | Frontier reasoning, the largest jobs |
| `claude-opus-4-8` | Opus | 1M tokens | Text, image, tool use | Hardest reasoning, long-horizon agents |
| `claude-sonnet-4-6` | Sonnet | 1M tokens | Text, image, tool use | Balanced quality and speed — the everyday default |
| `claude-haiku-4-5` | Haiku | 200 k tokens | Text, image, tool use | High-volume, latency-sensitive tasks |

<Callout type="note" title="Model id format">
Anthropic model ids follow the pattern `claude-{tier}-{version}` (e.g. `claude-sonnet-4-6`). New versions ship regularly and older ids are deprecated then retired — always confirm the current id list in the [models overview](https://platform.claude.com/docs/en/about-claude/models/overview). Claude Code defaults to a recommended Sonnet unless you override `model` in `settings.json` or pass `--model` on the CLI. Opus 4.7 and later use a new tokenizer that can spend up to ~35% more tokens on the same text, so budget by tokens, not by characters, when you switch tiers.
</Callout>

## Discounts and premiums

- **Batch API** — asynchronous processing at a flat **50% off** both input and output. Use it for anything not latency-sensitive (backfills, evals, bulk classification).
- **Prompt caching** — a cache read costs 10% of base input. A 5-minute cache pays for itself after one reuse; a 1-hour cache after two. Claude Code caches system-prompt content automatically; direct API callers opt in with `cache_control` breakpoints.
- **1M-token context** — Fable 5, Opus 4.8/4.7/4.6, and Sonnet 4.6 include the full 1M window at standard per-token pricing (a 900k-token request bills at the same rate as a 9k one). This 1M context can require credits to be enabled on your account.
- **Fast mode** (research preview, Opus only) — faster output at a premium: Opus 4.8 at $10 / $50 per MTok, Opus 4.6–4.7 at $30 / $150. Not available with the Batch API.
- **US-only data residency** (`inference_geo: "us"`, Opus 4.6 / Sonnet 4.6 and later) — a 1.1× multiplier on every token category.

## Cost-tiering quick guide

Use the table below alongside the [Cost-tiering chapter](/c/cost-tiering) to match model to task.

| Task type | Recommended tier | Reason |
|---|---|---|
| Exploration, brainstorm, first drafts | Haiku | Cheap, fast, good enough for idea generation |
| Code generation, refactor, standard tasks | Sonnet | Strong quality at moderate cost |
| Architectural review, complex reasoning | Opus | Maximum capability when correctness matters most |
| CI lint / quick checks | Haiku | Runs many times; savings compound |
| Final code-review pass | Sonnet or Opus | Stakes are higher; invest accordingly |

<Callout type="note" title="Token estimation rule of thumb">
Roughly 1 token ≈ 4 characters of English text. A 200 k context window holds approximately 150 000 words — about the length of a long novel — though code and structured data skew higher per token.
</Callout>

## Context window budget at a glance

| Slot | Typical size | Notes |
|---|---|---|
| System prompt (CLAUDE.md + injected) | 2 k – 20 k | Cached by Claude Code automatically |
| Conversation history | Grows with turns | Compacted when near limit |
| File content injected via Read | Varies | Large files consume budget fast |
| Tool results | 0.5 k – 5 k per call | Each tool call + result adds to context |
| Output reservation | ~8 k | Reserved for the model's response |
